# 选题和文案

## 选题

- 先查需求：`python3 tools/bili_kw.py "关键词1" "关键词2"` 列出 B站该关键词前 6 条视频的播放量、发布时间、时长。报 `CERTIFICATE_VERIFY_FAILED` 时换系统自带的 `/usr/bin/python3` 跑（它不依赖 whisper，用哪个 Python 都行）。
- 好选题 = 搜索量大 + 现有视频旧（界面过时、版本过时）+ 观众正好是目标用户。例：某关键词头部视频 1.5 万–9.6 万播放、多是 2–4 年前的，就值得做。
- B站要的是有用的教程，不是广告：一条 52 秒广告式短片发出去 7 小时 22 播放；3 分钟实用教程表现明显更好。
- 系列视频：上一期结尾预告了什么，下一期就做什么；没预告时自己选题，给主选 + 备选两个方案让用户挑，并说明各自需要什么素材（比如需要用户提供后台截图）。

## 标题

- 标题 = 观众会搜的词，不是口号。例："Nginx 配置 SSL 证书全流程：开启 HTTPS、强制跳转、5 个常见报错排查"。
- 标题、开场第一句、封面三者要覆盖本期讲到的每一类内容。讲了"四类方案"，封面就是四类，不能只放其中几个工具名。

## 长度

字数按字幕版文案（`script.md` 正文）计，不含标题和章节名。

| 语速 | 字数/分钟 | 实测 |
|------|-----------|------|
| 自然语速 | ~275 | 用户嫌慢 |
| 1.3x（默认） | ~360 | 1091 字 → 3:05；1239 字 → 3:18；1270 字 → 3:40 |

- B站教程控制在 3–3.5 分钟，约 1100–1250 字。第一版被嫌"文案有点多"时，按用户给的比例整体砍（常见 30%），不要只删一两句。
- 审批前没法实测，按 360 字/分钟估，英文术语、字母拼读多的按 300 字/分钟估，并写明"配音后以实测为准"。
- 竖屏短视频 20–35 秒，7 句左右。

## 结构

```
【开场】2–3 句：观众的问题 + 本期讲什么（覆盖全部类别）
【章节 1..n】每章 2–5 句，一章一个主题，章名就是章节条上的标签（2–4 个字）
【产品】1–2 句：只在用户要推广自己的产品时加；平实描述能解决哪一步，不讲价格
【结尾】互动一句（"你踩过哪个坑？评论区说说"）+ "觉得有用，点个关注"
```

【产品】和【结尾】各自也是一个章节，会出现在章节条上。

## 事实核查

在发文案审批之前做完：

- 每个数字、日期、默认行为都对照官方文档或源码（记下版本和日期）。能复现的命令和报错，先在 Docker 里实际跑一遍再写进文案（实验脚本放 `lab/`，第 4 步直接拿它的输出做画面）。
- 文档互相矛盾、找不到发布公告、自己无法验证的，不写进口播。
- 讲到竞品或第三方产品，只说核实过的功能；"没找到"不等于"不支持"。
- 推广的产品能做什么，以用户说的和它当前主分支代码为准；用户说"已经支持了"就先拉最新代码确认。

## 审批

1. 文案写进 `script.md`（标题 + 【章节】分段），完整发给用户，附估算时长，等明确同意。
2. 用户只回"继续/开始/可以的"也算同意；如果消息里给过 A/B 选项而用户没选，按你声明过的默认项执行，并在交付时说明。
3. 配音阶段为读音改过的每一处措辞（加"所以/先看"、换成中文说法），交付时逐条列出。

## 合规（跨平台发布）

- 画面、封面、文案里不放指向真实站点的网址、二维码、微信号等联系方式；不写"可以看看/看一下/搜一下/了解一下"这类引导，也不让观众转发。`example.com` 这类保留示例域名不算导流，可以出现在演示界面和终端里。
- 小红书：推广站外产品（包括教程、种草、展示其界面）会被判"推广其他平台"限流；只发不带产品的知识内容，除非用户选择付费投放。
- 不讲价格（单价、一年多少钱、按量付费），卖点放在功能上。
- 视频会多平台分发，不拿 B站、抖音等内容平台自己的网站当示例；需要真实站点做演示时用 `example.com`。平台名只出现在该平台自己的发布文案里。
- 抖音、视频号关于品牌露出的官方规则没找到时，不要向用户保证"安全"，说明查过什么、没查到什么。

## make_script.py 格式

```python
P = lambda caption, say: [caption, say]

CHAPTERS = [("开场", 0), ("证书文件", 3)]

L = [
 ("给 Engine X 配 H T T P S，配置只有十来行。", [P("给 Nginx 配 HTTPS", "给 Engine X 配 H T T P S"), "配置只有十来行"]),
 ("但很多人卡在后面。", ["但很多人卡在后面"]),
 ("这期再过一遍五个常见报错。", [P("这期再过一遍 5 个常见报错", "这期再过一遍五个常见报错")]),
 ("先说文件。Engine X 要的就两个：证书和私钥。", [P("先说文件。Nginx 要的就两个", "先说文件。Engine X 要的就两个"), "证书和私钥"]),
]
```

- `L` 每项：第一列是送给 TTS 的整句；第二列是字幕段，每段一屏（中文 20 字左右以内），按逗号切。
- 字幕和读法不同时用 `P(字幕, 读法)`；不同的段直接写字符串（字幕即读法）。**各段读法按顺序拼起来，去掉空格和标点后，必须等于整句 TTS 文本**，估时和对齐都依赖这一点。
- `CHAPTERS` 是 `(章名, 起始句号)`。脚本据此给章节首句加 `chapter` 字段、给章节末句设 0.5s 停顿（其余句间 0.1s）；`build_audio.py` 把 `chapter` 带进时间轴，页面和章节时间戳都从时间轴读。
- 运行后生成 `audio/script.json` 和 `audio/lines.json`（纯 TTS 文本），并打印句数、字数、章节数。
